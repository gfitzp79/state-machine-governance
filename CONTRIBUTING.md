# Contributing Guidelines

Thank you for your interest in the State Machine Governance project.

**This repository operates primarily as a reference architecture and a living methodology for specification-driven security tooling.** It outlines a specific architectural thesis regarding the state-machine nature of governance and risk management operations.

Because this repository illustrates a cohesive, intentional data model and philosophy, **we generally do not accept pull requests that materially alter:**
- The database schemas and core ERD.
- The fundamental risk, policy, or control state machines.
- Additions of proprietary frameworks or vendor-specific tooling logic.

## How to Engage

While codebase contributions might be restricted, engagement on the conceptual level is highly encouraged:

### 1. Discussions & Bug Reports
If you find typos, broken links, or inconsistencies in the reference architecture markdown sheets, please **Open an Issue**. 
If you simply want to discuss how to implement these patterns in your own custom pipelines, issues are the perfect venue for conversation. 

### 2. Forking 
The framework is published under CC BY 4.0. You are actively encouraged to fork this repository and extend it to fit your specific organisational workflows, regulatory needs, and integrations.

### 3. Pull Requests (Exceptions)
We will review PRs that are tightly scoped to hygiene improvements:
- Typo corrections in the existing specifications.
- Dead link fixes.
- Refinements to prompt engineering techniques in the Methodology directory that do not violate the core thesis.

Thank you for helping sharpen the concept of specification-driven governance.
